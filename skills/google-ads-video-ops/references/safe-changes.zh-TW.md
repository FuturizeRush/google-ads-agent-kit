# 修改與驗證

## 動手前

把使用者同意的目標整理成最小變更集合：哪個 campaign / ad group / ad、改哪些欄位、金額及幣別、總額或每日、日期與時區、要保留的限制。已明確同意的項目不用反覆確認；模糊的金額、範圍或新增花費則先問清楚。

重新讀取待修改欄位，私下保留舊值與物件關聯。若已經是目標值，列為 unchanged，不再儲存一次。若使用者或其他操作者剛改過，先重新核對，不用舊快照覆蓋新值。

檢查 audience、budget、asset 是否被其他對象共用。只授權修改一個 ad group 時，可在 UI 支援的情況下使用 **Edit a copy of this audience**，再把副本指派給目標；不要改動共用原件。複製 audience 並不授權複製 campaign、建立額外預算或啟動另一組花費。

## 執行

使用實際可用且已授權的寫入工具，或透過登入中的 Ads UI。只提供讀取功能的 MCP 不會因為 OAuth scope 較廣就自動具備 mutation；不要自行發明工具或改用未核准的認證方式。

在可行的情況下，先確認目的地、受眾與投放限制，再提高預算或啟用投放。不能原子更新多個欄位時，說明過渡狀態的花費風險；需要暫停／重啟或新增 campaign 才能完成，且未獲授權時，先停下詢問。

日期要以帳戶時區計算。已開始的 campaign 若無法修改起日，只能在授權內調整可編輯欄位，不宣稱重新開始完整週期。今日剩餘時間加後續完整日期，與精確的數個 24 小時不同；審查時間也不是有效投放天數。

UI 會延遲載入或重排。輸入日期後，確認已收合的摘要顯示正確日期；填入欄位、按 Enter 或點月曆格，不必然代表已提交選取。若操作落在錯誤區塊，重新讀畫面後修正，不連續盲點。

遇到 Google 身分驗證，由帳戶持有人完成正常驗證流程。不要求使用者貼上密碼、token、驗證碼，不從瀏覽器或設定檔挖取認證來繞過。工具回覆不明或 Save 逾時時，先讀回狀態再決定是否重試，避免重複建立或套用。

## 儲存後的證據

以重新開啟的表單／摘要或獨立讀取查詢核對持久化結果，不拿剛填入的表單值當驗證。依變更項目檢查：

| 改了什麼 | 必須核對什麼 |
| --- | --- |
| 預算與 bid | 同一 budget 的類型、幣別、總額／每日；active strategy 對應的 bid 欄位 |
| 日期及排程 | 起訖時間、帳戶時區、可編輯與不可編輯部分；排程是否真的存在 |
| Frequency | event 是 impression 或 view、cap、時間單位及作用層級；enum 要解碼，不直接猜數字 |
| Audience | 目標 ad group 綁定的新物件、實際條件、Unknown 與 expansion；共用原件及其他綁定未變 |
| 裝置／格式／network | 已保存的勾選狀態；不依未設定 scalar 的預設零值判斷排除 |
| 素材／落地頁 | ad 與 video / asset 身分、final URL、CTA、文案、保留參數、review 狀態 |

從 ad 移除影片不等於刪除影片平台上的影片。變更素材或 URL 後若重新審查，明確回報 pending；campaign enabled 不能替代 ad approval。

無法完成的項目保留為未完成，交代已落地的部分及最後驗證狀態。回復舊設定也可能再次影響審查或花費，不以「有舊值」暗示可以無風險自動 rollback。

最後把設定、審查、實際投放與轉換成效分別回報。需要之後追蹤時提供檢查點；只有使用者要求時才建立監控或提醒。
